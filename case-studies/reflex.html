FLAGSHIP // 04 · CASE STUDY

Reflex

A role-based delivery operations platform that replaces fragmented coordination with traceable assignment, controlled status transitions and secure recipient confirmation.

Completed & deployedNext.js 16 + React 19FastAPI + PostgreSQLWebSockets
THE SYSTEM

One operational record from creation to confirmation.

Reflex coordinates retailers, dispatchers, riders and recipients around a backend-authoritative delivery state. Each role sees the actions relevant to it, while invalid state transitions are rejected by the system.

DELIVERY FLOW
Retailer→Dispatcher→Rider→Delivered→QR Confirmation→Completed
CORE CAPABILITIES

Role-aware workflows

Retailer, Dispatcher, Rider and Admin experiences around one delivery lifecycle.

Controlled transitions

Delivery state is validated on the backend rather than trusted from the browser.

Secure confirmation

Single-use recipient QR confirmation through a narrow token-based flow.

Real-time updates

Authenticated role-aware WebSockets keep operational state synchronized.

Map context

Leaflet, OpenStreetMap and server-side geocoding support location context.

Transactional notifications

Email notification paths are separated so messaging failure does not undo core delivery actions.

ENGINEERING PRINCIPLES
  • Backend-authoritative workflow state
  • Role-aware access
  • Single-purpose recipient confirmation
  • Authenticated real-time updates
  • Explicit operational trade-offs
